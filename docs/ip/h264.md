# Bộ mã hoá H.264 (`bow_h264`)

Bộ mã hoá video H.264 / AVC tự viết của Bow32: nhận đầu ra của ISP (YUV 4:4:4,
1 pixel/clock) và tạo **byte stream H.264 Annex B** chuẩn, giải mã được bằng
mọi trình phát (FFmpeg, VLC, trình duyệt). Mã RTL: `hw/ip/h264/rtl/`. Mô hình
tham chiếu bit-exact + bộ giải mã nhỏ: `tools/h264/h264_model.py`. Driver:
`sw/common/include/bow_h264.h`.

```
 ISP m_axis ──► input ──► strip buffer ──► macroblock engine ─────────► coefficient buffer
 (YUV 4:4:4)    4:2:0     4 × 16 dòng       dự đoán intra 16x16          (2 macroblock)
 vid_clk        chia slot (UltraRAM)        chọn mode (SAD)                    │
                                            DCT 4x4, lượng tử, DC Hadamard     ▼
                                            IDCT, tái tạo ──► line buffer   CAVLC
                                                                               │ token ≤ 32 bit
   m_axis (clk_i) ◄── FIFO 2 clock ◄── word 32 bit ◄── emulation prevention ◄── bit packer
   → DMA kênh 0
```

| Thông số | Giá trị |
|----------|---------|
| Chuẩn | ITU-T H.264, **Constrained Baseline** (profile 66, constraint_set0/1), level ≥ 4.1 |
| Kiểu mã hoá | Intra only: mỗi frame là **một IDR slice**, mọi macroblock là `I_16x16`, entropy **CAVLC** |
| Dự đoán | luma 16x16: V, H, DC, plane; chroma 8x8: DC, H, V, plane — đủ 4 mode mỗi loại |
| Chọn mode | SAD nhỏ nhất trên 256 (luma) / 2 × 64 (chroma) mẫu, so với hàng xóm **đã tái tạo** |
| Lấy mẫu chroma | 4:2:0: trung bình làm tròn của mỗi khối 2x2 (vị trí chroma "center", báo trong VUI) |
| QP | 10…51, một QP mỗi frame (`QP`, firmware điều khiển tốc độ bit) |
| Kích thước | rộng bội số 16, tối đa `MaxWidth` (2048); cao chẵn ≤ 4095 (không bội số 16 → crop trong SPS) |
| Deblocking | cờ trong slice header (`CTRL.DEBLOCK`): bộ lọc chạy **trong bộ giải mã**; vì là intra only nên encoder không cần lọc |
| Thông lượng | **392 chu kỳ/macroblock** (engine), 200 MHz → 510 000 MB/s: 1080p tới ~62 fps, 720p ~140 fps |
| Đầu ra | word 32 bit, byte đầu ở bit [7:0]; mỗi frame = một NAL `00 00 00 01 65 …`, đệm byte 0 tới bội số 4, `tlast` ở word cuối |
| SPS / PPS | phần mềm viết (`bow_h264_write_headers()`), giống từng byte mô hình Python |
| Thanh ghi | peripheral bus `0x4000_9000`, ngắt `irq_fast[8]` |
| Tài nguyên (KV260) | ~13 400 LUT (cùng DMA), 6 URAM, 7 BRAM, 20 DSP; timing đạt ở 200 MHz |
| Trên board | camera IMX219 720p30 và 1080p30 thời gian thực, không bỏ pixel ([../video_kv260.md](../video_kv260.md)) |

## Vì sao như vậy

Mục tiêu là một encoder **đọc hiểu được** mà vẫn ra video thật: mỗi khối RTL
ứng với một mục của chuẩn, mọi phép tính có trong mô hình Python, và stream
giải mã được bằng FFmpeg. Những lựa chọn chính:

- **Intra only.** Frame P cần một frame tham chiếu đã tái tạo (720p: 1,4 MB,
  1080p: 3,1 MB) cùng tìm chuyển động; frame I chỉ cần hàng xóm của từng
  macroblock. Toàn bộ encoder nằm trong FPGA, không cần DDR.
- **Intra 16x16 thay vì 4x4.** Vòng phụ thuộc chỉ ở mức macroblock (MB sau cần
  cột phải đã tái tạo của MB trước), không phải mức khối 4x4: pipeline đơn giản,
  1 hàng 4 mẫu/clock.
- **Strip buffer thay vì frame buffer.** Mã hoá theo hàng macroblock ngay khi đủ
  16 dòng: 4 strip × 16 dòng × 2048 pixel nằm trong 6 UltraRAM.
- **Bộ lọc deblocking ở decoder.** Dự đoán intra dùng mẫu *trước* khi lọc
  (chuẩn H.264), nên với stream toàn intra encoder không cần lọc mà vẫn bật được
  bộ lọc trong decoder cho hình đẹp hơn.

## Các khối

### Đầu vào và strip buffer

Pixel `{V, U, Y}` từ ISP (CSC phải bật). Y vào strip buffer luma (8 pixel/word
64 bit). Chroma: ở dòng chẵn tổng từng cặp `U(2x) + U(2x+1)` vào line buffer,
ở dòng lẻ `Cb = (tổng dòng chẵn + tổng dòng lẻ + 2) >> 2` (tương tự Cr).

Strip buffer có `NumStrips` = 4 slot × 16 dòng. Slot được cấp theo thứ tự khi
dòng đầu tiên của strip tới, strip được giao cho engine khi đủ dòng, engine trả
slot khi đã đọc xong. Hàng cuối của frame có chiều cao không chia hết 16: engine
lặp lại dòng cuối (`strip_t.last_line`).

Khi encoder chậm hơn camera, pixel của strip không có slot bị **bỏ**
(`STATUS.ERR_OVF`), nhưng strip vẫn được mã hoá (bằng dữ liệu cũ) nên stream
**luôn hợp lệ**. Frame ngắn hơn `SIZE` (SOF sớm, `CTRL.EN = 0` giữa frame) được
hoàn tất tương tự (`ERR_INPUT`). Dòng dài hơn / frame cao hơn bị cắt.

### Engine macroblock

Mỗi macroblock (raster order) đi qua các pass, mỗi pass 1 hàng 4 mẫu/clock:

| Pass | Chu kỳ | Nội dung |
|------|-------:|----------|
| hàng xóm + setup | 6 | hàng trên (line buffer), cột trái (MB trước), góc trên trái; DC, a, b, c của plane |
| luma MD | 64 + 6 | SAD của V, H, DC, plane trên 16 khối 4x4 |
| luma forward | 64 + 11 | residual → DCT → lượng tử AC; W(0,0) → DC |
| luma DC | 18 | Hadamard, lượng tử, ngược lại |
| luma inverse | 64 + 11 | giải lượng tử, IDCT, + dự đoán → tái tạo, giữ cột phải / hàng dưới |
| chroma (Cb + Cr) | 32 × 3 + … | cùng các bước với 8 khối 4x4 |
| kết thúc | 1 | level + thông tin MB sang CAVLC, hàng dưới vào line buffer |

Tổng **392 chu kỳ/MB** (đo trong testbench). CAVLC chạy song song trên MB trước.

### Quyết định của encoder (phải giống hệt mô hình)

Các bước của bộ giải mã (dự đoán, giải lượng tử, IDCT, tái tạo) là chuẩn H.264
(clause 8). Các *quyết định* sau là riêng của encoder này, RTL và mô hình làm y
hệt nhau:

```
chroma 4:2:0     C = (c(2x,2y) + c(2x+1,2y) + c(2x,2y+1) + c(2x+1,2y+1) + 2) >> 2
mode luma        SAD nhỏ nhất trong các mode có hàng xóm, hoà thì mode số nhỏ:
                 V(0) < H(1) < DC(2) < plane(3)
mode chroma      DC(0) < H(1) < V(2) < plane(3), SAD = SAD(Cb) + SAD(Cr)
lượng tử AC      level = sign(W) · min((|W| · MF(QP%6, vị trí) + f) >> (15 + QP/6), 2063),
                 f = floor(2^(15+QP/6) / 3)
DC luma          Y = (H D H) >> 1 (dịch số học), level = sign · ((|Y| · MF0 + 2f) >> (16 + QP/6))
DC chroma        Y = H2 D H2,                      cùng công thức lượng tử
CBP              luma = 15 nếu có level AC ≠ 0; chroma = 2 nếu có AC ≠ 0, 1 nếu chỉ DC ≠ 0
mb_qp_delta      0 (QP của slice)
idr_pic_id       0, 1, 0, 1… từ START
```

`|level| ≤ 2063` là giá trị lớn nhất CAVLC mã được với suffixLength 0 (prefix
15 + 12 bit), nên mọi level đều mã được. QP tối thiểu 10 giữ các hệ số sau giải
lượng tử trong 16 bit như bộ giải mã yêu cầu.

### CAVLC

Khối F đọc 4 word (chroma DC: 1) của một khối 4x4, xếp theo zig-zag, đếm
TotalCoeff / TrailingOnes, tính nC từ TotalCoeff của khối trái / trên (MB hiện
tại, MB bên trái, line buffer của hàng MB trên). Khối E phát lần lượt
`coeff_token` (+ dấu trailing ones), các level (suffixLength thích nghi),
`total_zeros`, các `run_before`; một tầng cuối tra bảng thành mã. F chuẩn bị
khối sau trong khi E phát khối trước.

Thứ tự trong một MB (clause 7.3.5): `mb_type` (= 1 + mode + 4 · cbp_chroma +
12 · (cbp_luma ≠ 0)), `intra_chroma_pred_mode`, `mb_qp_delta`, Intra16x16DCLevel,
16 × AC luma (nếu cbp_luma), 2 × DC chroma (nếu cbp_chroma ≥ 1), 8 × AC chroma
(nếu cbp_chroma = 2).

### Stream

```
00 00 00 01 67  SPS   (phần mềm, 1 lần)       profile 66, level, kích thước, crop, VUI:
00 00 00 01 68  PPS   (phần mềm, 1 lần)         BT.709, video/full range, fps
00 00 00 01 65  IDR slice  frame 0   (encoder)  first_mb 0, slice_type 7, frame_num 0,
00 00 00 01 65  IDR slice  frame 1               idr_pic_id, slice_qp_delta, deblocking
…
```

Mỗi NAL được đệm byte 0 tới bội số 4 (trailing_zero_8bits của Annex B), nên mỗi
frame bắt đầu ở địa chỉ chia hết cho 4 trong bộ nhớ. `tools/h264/mp4.py` đóng
gói stream thành MP4 (không cần ffmpeg).

## Hai miền clock

| Miền | Clock | Nội dung |
|------|-------|----------|
| CPU | `clk_i` (50 MHz) | thanh ghi, đầu ra `m_axis` (sang DMA) |
| Video | `vid_clk_i` (200 MHz trên KV260) | toàn bộ encoder |

EN / DEBLOCK qua `bow_sync`; START, STOP, cập nhật QP, FRAME_DONE, DONE và lỗi qua
`bow_cdc_pulse`; SIZE, FRAMES, SKIP là cấu hình tĩnh (chỉ đổi khi `EN = 0` /
trước START); đầu ra qua `bow_fifo_async` 512 word (2 ràng buộc `set_bus_skew`
trong `kv260_cam.xdc`).

## Bản đồ thanh ghi (`0x4000_9000`)

| Offset | Tên | Truy cập | Mô tả |
|-------:|-----|:--:|-------|
| 0x000 | `ID` | R | `0x48323601` ("H26", phiên bản 1) |
| 0x004 | `CTRL` | RW | [0] EN, [1] DEBLOCK (slice header bật bộ lọc của decoder) |
| 0x008 | `CMD` | W | [0] START: mã hoá từ start of frame kế tiếp, [1] STOP: không bắt đầu frame mới |
| 0x00C | `STATUS` | R/W1C | [0] BUSY, [1] FRAME_DONE, [2] DONE (đủ FRAMES frame), [3] ERR_OVF, [4] ERR_INPUT, [5] ARMED |
| 0x010 | `IRQ_EN` | RW | bit 1..4 như `STATUS` → `irq_fast[8]` |
| 0x014 | `SIZE` | RW | [11:0] rộng (bội số 16), [27:16] cao (chẵn); chỉ đổi khi EN = 0 |
| 0x018 | `QP` | RW | 10…51 (bị kẹp), dùng từ frame bắt đầu sau khi ghi |
| 0x01C | `FRAMES` | RW | số frame mã hoá sau START, 0 = tới STOP |
| 0x020 | `SKIP` | RW | số frame vào bị bỏ sau mỗi frame được mã hoá |
| 0x024 | `FRAME_CNT` | R | frame đã mã hoá từ START |
| 0x028 | `FRAME_BYTES` | R | kích thước frame vừa xong (byte, bội số 4) |
| 0x02C | `FRAME_CYCLES` | R | chu kỳ video từ start of frame của nó tới cuối NAL |
| 0x030 | `MB_CYCLES` | R | chu kỳ engine macroblock làm việc từ START |
| 0x034 | `INFO` | R | [15:0] `MaxWidth`, [19:16] số strip |
| 0x038 | `TOTAL_BYTES` | R | byte từ START |

## Lập trình

```c
#include "bow32.h"

bow_h264_params_t p = {.width = 1280, .height = 720, .fps_num = 30, .fps_den = 1};
uint8_t *buf = (uint8_t *)BOW32_VRAM_BASE;
uint32_t hdr = bow_h264_write_headers(buf, 256, &p);         /* SPS + PPS */

bow_dma_stream(0, buf + hdr, BOW32_VRAM_SIZE - hdr, false); /* encoder -> VRAM */
bow_h264_init(1280, 720, 30, true);                         /* QP 30, deblocking */
bow_h264_start(30, 0);                                      /* 30 frame */
while (!(H264->STATUS & H264_ST_DONE)) {
  if (H264->FRAME_CNT != n) { n = H264->FRAME_CNT; bow_h264_set_qp(...); }  /* rate control */
}
/* stream: buf[0 .. hdr + DMA->CH[0].PKT_END), DMA->CH[0].PKT_CNT frame */
```

ISP phải xuất YUV (`ISP_MOD_CSC`); ứng dụng `sw/apps/video` nạp ma trận BT.709
video range (Y 16…235) và báo `full_range = false` trong SPS. Ứng dụng đầy đủ
(camera, AE/AWB, điều khiển tốc độ bit, truyền qua UART):
[../video_kv260.md](../video_kv260.md).

## Bài tập mở rộng

- Intra 4x4 (9 mode) cho vùng nhiều chi tiết: nén tốt hơn rõ rệt.
- Frame P với `P_Skip` + tìm chuyển động nhỏ: cần frame tham chiếu (DDR của PS).
- Rate control trong phần cứng theo hàng macroblock (`mb_qp_delta`).
- Nhiều slice mỗi frame, CABAC (Main profile).
- 2 engine macroblock song song cho 1080p60.
